# CH584 屏幕验证助手

本工具对应当前 `D:\蓝牙模块优化\CH584_V1_0_1` 固件，通过电脑串口替代外部主控发送页面帧，辅助区分“页面协议未收到”和“屏幕驱动或硬件问题”。没有修改、编译或烧录 CH584 固件；参考工具及其配置保留原样。

工具只允许发送 `0x01` 页面帧和 `0x03` 传感器读取请求。`0x04` 解绑、`0x05` 保存、`0x07` 恢复出厂以及其它命令均不允许发送；导入 XML 或使用原始 HEX 输入也须经过相同检查。`Rank=5` 屏幕重新初始化属于 `0x01`，会影响显示，须主动点击相应测试功能。

## 接线和串口

通信端为 CH584 的 UART3，串口设置 **115200、8数据位、无校验、1停止位、无流控（8N1）**。使用与板卡 IO 电平匹配的 USB-TTL 适配器，不使用 RS-232 电平接口。

| USB-TTL | CH584 | 用途 |
|---|---|---|
| TX | PA4（UART3 RX） | 电脑发送页面帧 |
| RX | PA5（UART3 TX） | 电脑接收应答、主动上报 |
| GND | 板卡 GND | 共地 |

电脑替代 STM32 主控测试时，先断开 **STM32 TX → CH584 PA4** 的原连线，避免 STM32 和 USB-TTL 两个 TX 输出并联。UART3 接线依据 `APP\Usart3_task.c` 的 `Usart3_Init()`，驱动默认9600会被该函数覆盖为115200。板卡继续按原来的供电方案供电；适配器 VCC 不应在没有确认电压和供电关系时直接并联到板卡。

如需查看 `[BOOT] 1…10` 启动进度，可使用第二个 USB-TTL 适配器：**RX ← PA9（UART1 TX），GND共地，TX不连接**。它同样使用115200 8N1，并选择另一个 COM 口。通信 COM 与调试 COM 不能相同，也不能同时被其它串口软件占用。UART1 输出包含文本，不应按 UART3 的 AA EE 二进制协议解释。连接调试口后重新上电或复位才能观察完整启动记录。

## 最短屏幕验证步骤

1. 完成上述接线，在程序中刷新串口列表并连接 UART3 通信 COM。程序启动、刷新列表和构建自测不会自动连接串口。
2. 首先点击“持续发送主页”，默认每200ms保持显示；此后再测试“开始页面轮播”。主页有10个固定参数，标准帧如下，共32字节，LEN=26，SUM=8C。
3. 若主页仍空白，使用第二适配器看启动进度。看到 `[BOOT] 3 u8g2Init` 只说明打印到这里；看到 `[BOOT] 4 fifo_init` 才说明屏幕初始化函数已经返回。看到 `[BOOT] 10 Main_Circulation` 说明主函数执行到主循环入口；这些日志不证明 UART3 收到页面帧或屏幕已经显示。
4. 可主动点击一次“初始化后显示主页”验证。程序发送 `Rank=5` 请求后等待1300ms，再清除提示、发送正常主页并保持心跳。单独发送 `Rank=5` 会清屏，固件的该等级不绘制正常内容，持续发送会干扰正常显示。
5. 需要传感器读取时发送一次 `0x03`。当前固件等待本轮数据收齐或30秒超时后回复；不要把没有立即应答当作串口已失败。该命令还会清本轮新鲜度标记并开始一次等待，不写 Flash。

```text
AA EE 00 1A 01 00 01 00 00 0A 00 0A 01 72 00 01
00 00 00 01 00 01 00 00 00 00 00 00 00 00 8C 0A
```

参数依次为 `[10,370,1,0,1,1,0,0,0,0]`，字段为Sensor=0、Rank=1、Menu=0、Focus=0。SUM只累计CMD及后面的载荷字节，按256取模；不包含帧头、LEN和帧尾。读取请求固定为 `AA EE 00 01 03 03 0A`。

**TX日志表示电脑将字节提交给串口驱动，不代表 CH584 实际收到了它，更不代表屏幕绘制成功。** 当前固件没有为每条 `0x01` 页面帧发送确认应答。RX里的 `0x03` 应答或 `0x06` 上报证明通信端收到了有效数据，但仍不能代替屏幕观察或 SPI 波形测量。

## 页面与参考 XML 的差异

程序支持参考工具的 `ArrayOfPageSpec/PageSpec` XML 字段结构，导入后保留原字段，逐页提示其与当前固件的兼容性。结构兼容不等于页面协议兼容，工具不会凭旧标签推测或自动补齐新参数。

| 内容 | 当前固件与工具约束 |
|---|---|
| 首页 Rank=1 | 至少10个固定参数，最多30个；旧工具9参数首页不允许发送 |
| 菜单 Rank=2/3 | Menu0…6对应参数总数4、8、16、23、8、5、10，包含最后两个页面元数据（页码与子页选择） |
| 当前 Menu=6 | 入口是“信息汇总”；旧XML中的“初锚力值页”不能直接映射到它 |
| Rank=6 | 单参数为提示码；1…7短时结果提示，8/9常驻开关机提示，0清除提示。不是Menu=6，也不是普通页面等级；先发送普通主页再测试提示 |
| Rank=5 | 屏幕重新初始化请求，参数为空；初始化会清屏，须随后回主页 |
| 页面停留时间 Delay | 50…60000ms，默认1500ms；与200ms心跳间隔分别设置 |

参考文件 `D:\y\tools\页面轮播\初锚力版\初锚力页_重置返回切换_50ms.xml` 有4个旧初锚力页面，Rank为2/3、Menu=6、参数只有4个；可导入查看，但这4页均不符合当前Menu=6所需10参数，工具拒绝发送它们。原工具还包含 `0x02` 单双通道切换功能，本工具没有沿用。

默认轮播只勾选普通查看页面，重新初始化、结果提示、绑定扫描子页及恢复出厂确认页不默认轮播。`0x01` 页面仍可能影响固件的扫描模式：进入设备绑定的绑定子页（Rank3/Menu2、最后参数re_flag=2）会切换到发现绑定模式，应按测试目的主动选用。

停止发送后，当前固件在最后一条合法 `0x01` 的帧龄超过5秒时关闭刷新门控。**它只停止刷新，不自动发送清屏或关闭供电，原有画面通常保持。** 发送一次主页能重新打开门控；心跳让页面持续可刷新。电脑关闭程序或断开连接也没有自动清屏协议。

XML空文件、格式错误、空页面数组、错误根节点、重复Labels/Values节点、缺失Values节点、标签与参数数量不一致、参数超出0…65535及DTD均应拒绝加载。缺失或空Labels会生成“参数1…n”显示标签；参数值与页面字段保持原样，仍需通过当前协议检查后才能发送。相同的标签文字可以用于不同参数；“重复节点”是指同一PageSpec里出现多个Labels或Values容器。

提示8/9不会按普通结果提示自动消失，需发送Rank6/msg=0清除，然后再发主页。“持续发送主页”按钮会先自动清除提示；手工输入的普通主页帧或其它普通页面心跳本身不能清除常驻提示。

“收发与启动日志”页保留发送、UART3接收和UART1启动文本的独立显示；日志追加保存在本目录 `logs\日期时间_随机编号.tsv`。新会话使用新文件，“清空显示”只清窗口内容，已有日志文件仍保留。“通道数据 03 / 06”页解码有效 `0x03/0x06` 的20通道类型、原始值和电压，最近接收时间用于判断数据是否过期。

发送前日志写入失败时，本帧不会提交串口；若串口已写入而结果日志保存失败，会明确提示“已提交串口”。两种情况都会停止自动发送并锁定后续发送，解决目录或磁盘问题后重新启动程序。串口断开及重新连接时，通道表会清除上一连接数据，避免误判。

50ms 是普通 Windows 程序的目标停留时间，不保证实时精度；高负载或串口阻塞可能使实际间隔增大。日志时间用于核对电脑提交时间，不能代替板上 UART/SPI 波形测量。
