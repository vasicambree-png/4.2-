# 绑定与解绑返回、解绑隐藏 MAC

## 保存后旧页面帧覆盖的复现与修正

用户确认保存提示出现、结束后仍回绑定子页，实际烧录目录为 `CH584_V1_0_1/obj`。核对时该目录HEX与上一轮独立构建HEX的SHA256完全一致，因此没有证据将现象归因于旧文件。上一轮页面等级修正只处理二级页残留re_flag，不能阻止主控重新发送完整三级绑定页。

本轮使用实际 `parse_received_frame` / `app_uart_process` / `usart_ProcessEvent`，并首次在UART测试中使用实际 `ui_show_msg` / `ui_msg_tick_sec`：先进入绑定三级页，再同一次UART消费输入0x05及旧三级绑定页帧，之后持续输入旧页帧并推进真实提示倒计时。修改前274项检查中30项失败，可重现保存后立刻回三级、提示结束仍留子页；这证明代码存在该覆盖路径，现场具体收发帧尚未采集。

`Usart3_task.c` 新增保存返回待确认标志，仅由绑定子页的合法0x05置位。后续同三级绑定页帧照常解析业务参数，但页面保持二级设备绑定菜单、绑定设备焦点、re_flag=0和DATA扫描模式；提示或屏幕重新初始化不解除标志，非法帧不能解除。收到合法上级页面、首页或其他普通页面后解除，允许再次进入绑定页。原Flash保存、响应状态和提示时长保留，一键解绑路径未改。

协议边界：主控一直只发相同三级绑定帧时，屏幕无法区分旧页刷新和再次进入；要重新进入，主控必须先发送上级菜单或其他普通页面。完整的主控按键状态同步仍应由STM32端实现，当前仓库不包含它。若现场仍失败，请采集UART3保存前后收发帧，不能凭软件复现断言现场唯一根因。

最终339项UART回归0失败，覆盖成功/空/失败、同突发及提示结束后的旧帧、业务参数缓存、息屏计时不被旧刷新重启、非法父帧、提示/reinit、父页/首页/其他三级页确认后重入。MSVC保留已有C4101/C4244警告。WCH独立目录及实际obj目录均编译/链接成功，日志无warning/error；FLASH 212568 B，RAM 66176 B，两份HEX哈希一致。最新可烧录文件为 `CH584_V1_0_1/obj/CH584M_TFT_HB.hex`。

本轮烧录、UART现场采集与实屏行为**尚未验证**。最短验收：烧录obj目录本轮HEX，保存并等待提示结束，应停在上级菜单；随后返回并再次进入绑定页，确认主控已发送上级页面且可以重新进入。检查保存后重启恢复仍需真实硬件，宿主Flash为桩。
