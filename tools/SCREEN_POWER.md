# 亮屏时间与实际关屏

## 使用方式

沿用现有“其他设置 → 亮屏时间”参数 `Menu_rank6.time_light`，单位为秒：

- `0`：常亮。
- 三级页面（`menu_rank=3`）：选择期间持续亮屏，停留或相同页面刷新均不触发超时关屏。
- `1..65535`：其他普通页面距最后一次可识别操作满指定秒数后关屏；退出三级页面时重新计时，保留原亮屏时间设置。
- 页面等级、菜单、焦点、首页分页、菜单子页/分页或亮屏时间改变，重新计时并唤醒。
- 电池、RSSI、通道数据和相同页面的周期刷新不续亮，熄屏时也不唤醒。
- 显式 `menu_rank=5` 屏幕重初始化请求也会唤醒。

当前协议没有独立按键活动码。同一页面、同一焦点且内容未改变的按键动作无法区分于普通刷新；主控若要让这种动作唤醒，可发送已有的屏幕重初始化请求，再发送实际页面。

亮屏时间仍来自主控 `0x01` 页面帧中 `menu_rank=2/3, rank2=5` 的第二个参数。收到完整合法设置帧后立即生效，本次未改变参数的保存/返回协议，也未增加 CH584 参数 Flash 存储。CH584 重启后默认值为 `0`，主控需重新下发已保存的亮屏时间；单独发送首页不会携带该设置。首次合法普通页面到达前，显示保持关闭。

## 数据接收与显示分离

`APP/Usart3_task.c` 的 `START_DATA_EVT` 每 20 ms 检查屏幕状态，只在状态变化时调用已有的 `u8g2_SetPowerSave()`。当前 ST7305 驱动将关闭/开启分别转换为 `0x28`/`0x29` 命令。它关闭显示，不切断 MCU 或屏幕供电，不启用 MCU 睡眠。

关屏仅限制 `UI_Control()` 绘图和非必要显示初始化。下面的原有数据路径继续执行：

- UART3 中断继续写接收 FIFO；主循环 `app_uart_process()` 继续取包和解析。
- 完整合法 `0x01` 帧继续更新 `Data_list1`，即使屏幕关闭。
- 10 ms 事件仍调用 `observer_adv_drain(16)`，BLE 数据继续解析并更新通道缓存。
- 秒事件的 `0x03` 应答、`0x06` 上报、扫描维护、绑定 Flash 保存继续运行。

唤醒后请求重画，使用最新页面状态和本地 BLE 通道缓存，不回放熄屏前的旧帧。这里的实时数据保存是运行内存缓存，断电不保留所有历史测量；绑定记录仍按已有机制保存到 Flash。本次没有新增测量日志或逐条写 Flash。

保留原有“最近 5 个秒事件内有有效页面帧”绘图条件，它独立于实际关屏计时：主控停止发页面时暂停刷新，非三级页面仍按设定的亮屏时间关屏。普通数据帧不能绕过关屏状态。非法、参数不足或校验失败的页面帧不更新熄屏计时。

三级页面例外：即使主控暂时停止发帧，显示也保持开启，但上述绘图新鲜度条件仍生效。`rank6` 保存提示和 `rank5` 重初始化不替换策略记录的最近普通页面，因此最近普通页面为三级时仍保持亮屏；主控退出选择后须下发真实的首页/二级等普通页面，才恢复超时计时。

`APP/include/screen_power.h` 使用 SDK 确认的 TMOS 时钟（0.625 ms/tick）计算截止时间，避免累计事件次数导致计时漂移。到点后锁存关闭状态，系统时钟回绕不会自行唤醒。

## 验证

执行策略测试：

```powershell
cmd /d /c tools\screen_power_tests\run_tests.cmd
```

执行串口任务宿主测试（使用本机 Python）：

```powershell
python tools\screen_uart_tests\run_tests.py
```

固件构建：在 MounRiver 打开原工程并构建。也可运行：

```powershell
& .\tools\screen_power_build\build_firmware.ps1
```

该脚本使用当前 `obj/` 的实际生成规则，在独立的 `tools/screen_power_build/output/` 编译全部固件并链接，产出 HEX；不覆盖 IDE 的 `obj/` 或主页预览产物。脚本核对构建前后源文件哈希，若其他对话在构建期间修改源文件，会报错并要求重跑。首次使用需要 IDE 已生成 `obj/makefile`。

2026-09-30 本轮检查：完整固件编译、链接成功，无编译警告/错误；策略测试 101 项、串口任务宿主测试 61 项检查通过。固件 FLASH 使用 322496 B / 448 KB，RAM 使用 66040 B / 96 KB。串口任务宿主测试直接抽取生产源中的完整相关函数并编译，外设、BLE、Flash 边界使用桩；MSVC 保留了原源码中 4 条未使用变量/整数截断警告。这些测试不证明真实 UART/BLE 电气通信或屏幕实际熄灭。

烧录与实屏效果尚未验证。最短实机检查：

1. 在具备烧录授权的环境使用本轮 HEX，先下发“其他设置”将亮屏时间设为 10 秒，再切回首页。
2. 持续发送相同页面、不同数据的合法帧，同时保持 BLE 传感器发送；约 10 秒后应关闭显示。
3. 保持熄屏继续发送，检查 UART 的 `0x03/0x06` 数据仍更新；改变菜单选择或分页后，应恢复显示最新数据。
4. 设置为 `0`，持续保持同一页面超过 10 秒，应保持显示开启。
5. 若超时后屏幕仍可见，检查屏幕型号、驱动命令及实际 SPI 信号，不能把宿主测试或编译通过当作实屏成功。

## 2026-10-07 三级选择期间保持亮屏
