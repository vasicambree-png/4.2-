# CH58x 4.2 寸 ST7306 屏幕工程

这是独立的 **4.2 寸屏幕固件仓库**：[vasicambree-png/4.2-](https://github.com/vasicambree-png/4.2-)。

**这里已包含完整 MounRiver 固件工程**：应用程序、WCH SDK 相关源码、预编译 BLE/ISP 静态库、U8g2 图形库、字库资源、工程配置和 4.2 寸 ST7306 驱动适配代码。文件从原 [2.9 寸工程](https://github.com/vasicambree-png/2.9-) 的指定提交导入，只在本仓库提交改动，不会写入 2.9 寸工程。

## 当前状态

- 已接入仓库原有的 `ST7306 300x400` 底层显示驱动，并修复部分初始化/传输错误。
- 已将 `u8g2Init()` 指向 ST7306；保留由 `SCREEN_PANEL_ST7306_42` 控制的 ST7305 回退选项（在 `CH584_V1_0_1/APP/include/yuying_TFT.h`）。
- 上电后可由固件触发 **边框 + 十字线 + 两个实心标记** 测试画面，便于仅连接屏幕和屏幕 MCU 时检查显示链路。
- **未在 MounRiver 进行实际编译、烧录或屏幕实测**；现有主页与多级菜单仍是原 `384×168` 固定布局，没有完成 `400×300` 物理屏的全页面重排。请先按下面步骤完成硬件冒烟测试。

## 在 Windows 上打开并烧录

1. 在 GitHub 仓库点击 **Code → Download ZIP**，解压完整仓库；也可以使用 Git 克隆：
   ```powershell
   git clone https://github.com/vasicambree-png/4.2-.git
   ```
2. 使用 **MounRiver Studio** 打开 `CH584_V1_0_1/CH584M_TFT_HB.wvproj`，核实 IDE 的目标芯片与实际芯片一致（旧工程名称带 CH584M，源码还包含 CH585 配置）。
3. 执行 **Clean Project → Build Project**，先解决可能出现的编译或链接错误；确认工程所需的 `.a` 静态库存在且被链接。
4. 核实 **4.2 寸实际屏幕驱动为 ST7306**、供电、接口、SPI 模式与复位时序；不允许仅凭屏幕尺寸判断兼容。
5. 烧录屏幕 MCU，先不接底板 UART，给板上电，检查测试画面是否完整；无画面时测量供电、RESET、SPI 时钟/片选/数据/DC，并读取 UART1 日志。
6. 最后接入底板 UART3，验证 BLE、页面更新、按键操作和所有菜单。原 384×168 页面需要进一步改版到新屏幕，测试图通过不代表 UI 适配完成。

## 主要文件

- `CH584_V1_0_1/APP/yuying_TFT.c`：显示初始化、主页及菜单绘制、上电几何测试图。
- `CH584_V1_0_1/APP/include/yuying_TFT.h`：4.2 寸配置开关和逻辑/物理尺寸。
- `CH584_V1_0_1/APP/Usart3_task.c`：无底板开机测试触发与显示状态机。
- `CH584_V1_0_1/u8g2/u8x8_d_st7305.c`：包含 ST7306 的 300×400 驱动实现。
- `CH584_V1_0_1/u8g2/u8g2_d_memory.c`：30 KB 显示缓冲区；ST7306 映射 600×400 虚拟像素用于 300×400 物理屏的数据格式。
- `CH584_V1_0_1/tools/ST7306_42_BRINGUP.md`：具体测试顺序和风险说明。

> 4.2 寸屏如果实际是 ST7305 而非 ST7306，**不要直接烧录此默认配置**。这份工程暂时是驱动接通和独立上电测试版本，未获得硬件实测认可。
